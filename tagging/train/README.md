# The original Gemma tagger — now the teacher

This is the **first-generation** lexide tagger: a LoRA finetune of **Gemma 4 31B** that
emits the whole analysis as tab-separated text (`idx⇥token⇥ws⇥POS⇥lemma⇥dep⇥head`).
It has been replaced as the online tagger by **parsley** (`../tagger/`, the small encoder
model), but it is NOT dead code — it remains load-bearing in three ways:

1. **Teacher.** The 2.7M silver sentences parsley trained on (`../data/big/`) were
   generated by this model. Any new silver — e.g. more jpn/kor/hin data to fix parsley's
   low-resource languages, or a new language — comes from here.
2. **Gold data.** `data/cleaned_*.jsonl` (11 languages, including `zho`, which parsley
   doesn't cover yet) is the human-cleaned gold set that `../tagger/data_prep.py` mixes
   into parsley's training data. Don't delete this directory.
3. **Japanese fallback.** parsley's jpn quality (POS 85 / LAS 65) isn't shippable; until
   it's fixed, Gemma is the only usable tagger for Japanese.

## Pieces

| What | Where |
|------|-------|
| LoRA training (TRL/peft, Lambda via `sky.yaml`) | `src/train.py`, `src/data_loader.py` |
| Eval / inference / distillation utilities | `src/evaluate.py`, `src/inference.py`, `src/distill.py` |
| Adapter on HF | `anchpop/lexide-gemma-4-31B-it` |
| vLLM serve (A100-80GB, scale-to-zero) | `../modal/modal_serve.py` → `https://anchpop--lexide-gemma-4-31b-vllm-serve.modal.run` |
| Rust client for its text format | lexide crate, `remote` feature (`Lexide::from_server`, `parsing.rs`) |

## Status / decommissioning

The Modal serves (a gemma-3 and a gemma-4 app are both still deployed) are
**scale-to-zero**, so keeping them deployed costs ~nothing while idle. Retire the serve
only when both are true: (a) downstream consumers (yap — note the lexide crate's
`RemoteConfig` default URL is still this endpoint) have switched to parsley, and
(b) Japanese is either fixed in parsley or explicitly gated. The training code + gold
data should stay regardless — they're the path to better silver.
